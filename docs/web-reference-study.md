# 웹·이력서 레퍼런스 조사 설계

## 조사 목적

최종 전략인 국내 전시·MICE 고객경험 프로젝트 코디네이터를 30초 안에 이해시키는 웹사이트를 만든다. 예쁜 사이트 모음이 아니라 채용자 탐색 흐름, 정보 계층, 프로젝트 증거, 모바일 가독성을 비교한다.

## 조사 도구와 역할

- `browser-research`: 공개 레퍼런스를 병렬 수집하고 URL·스크린샷·요소별 메모를 축적
- `Playwright`: 1440px·768px·390px에서 페이지 이동과 요소 상태를 반복 확인
- `ui-ux-suite`: 정적 HTML/CSS의 접근성·타이포·간격·반응형 감사
- `one-shot-ui`: 동일 모바일 뷰포트의 레퍼런스·구현 화면 비교

현재 사이트에 적용한 판단:

1. 첫 화면에서 직무 정체성과 세 역량 축을 동시에 노출
2. 장식용 수치 스트립 대신 스크롤형 강점 카드 사용
3. 경력을 회사 나열이 아닌 운영 → 고객 여정 → 디지털 개선 성장 흐름으로 재구성
4. 포트폴리오를 이미지 갤러리가 아니라 문제 → 설계 → 실행 → 증거로 연결
5. 실제 럭키드로우 데모와 현장 미디어를 첫 포트폴리오에 배치
6. 파스텔 색상은 배경·카드·프로세스에 넓게 사용하고 텍스트는 중성 보라회색으로 유지

## 적용하지 않은 패턴

- 근거 없는 구독자·조회수·프로젝트 수치
- 장식만 있는 인포그래픽
- 한 프로젝트에 모든 정보를 넣는 긴 첫 화면
- 외부 SaaS에 개인정보를 업로드하는 이력서 제작 방식
- 사용자가 직접 해석해야 하는 회사명 중심 트랙 카드

## 채용자 경험 QA 질문

- 첫 5초에 목표 직무가 보이는가?
- 첫 스크롤에서 강점 세 가지가 보이는가?
- 경력과 포트폴리오가 같은 메시지를 말하는가?
- 영상·iframe·이미지가 가로세로 비율을 유지하는가?
- 모바일에서 클릭 없이도 프로젝트 종류와 역할이 보이는가?
- PDF와 웹의 색·폰트·프로젝트 순서가 일치하는가?
