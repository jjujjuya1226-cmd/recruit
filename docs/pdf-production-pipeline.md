# 1페이지 PDF 전문 제작 파이프라인

## 최종 산출물

최종 제출용 PDF는 A4 세로 1페이지다. 내부에서는 ATS 구조안과 사람용 시각안으로 여러 번 실험할 수 있지만, 사용자에게 넘기는 최종본은 한 장으로 고정한다.

## 전문 역할

- 전략팀: 국내 PCO·전시주최사·전시장 운영사 기준의 핵심 메시지 결정
- ATS 구조팀: 텍스트 순서·섹션·키워드·추출 가능성 검증
- 증거보호팀: `verified_fact / estimate / inference / unknown` 상태 부여
- 레퍼런스 조사팀: 이력서·인포그래픽·편집디자인 사례를 출처와 함께 비교
- 편집디자인팀: 크림·피치·라벤더·세이지·베이비블루 파스텔 시스템 설계
- 한글 타이포그래피팀: Pretendard·온글잎박다현의 임베딩·줄바꿈 검수
- PDF 렌더팀: A4 렌더·페이지 수·텍스트 레이어 확인
- 채용자 레드팀: 5초 정체성·20초 강점 파악 테스트
- 회귀 QA팀: 렌더 이미지·내용·레이아웃 변화 검사

## 반복 루프

`resume.yaml 잠금 → 전략 요약 → 근거 감사 → 레퍼런스 비교 → 구조안 → 시각안 → PDF 렌더 → 채용자 레드팀 → 회귀 QA → 수정`

## 통과 기준

- A4 1페이지
- 첫 5초 안에 목표 직무와 차별점 확인
- 20초 안에 세 가지 핵심 축 확인
- 모든 핵심 주장이 SSOT에 연결
- 한글 글자 깨짐·겹침·잘림 없음
- ATS 텍스트 추출 가능
- 웹사이트와 포지셔닝·프로젝트 순서 일치
- 검증 전 수치를 확정 성과처럼 표현하지 않음

## 도구 역할

벤더 조사에서 확인한 후보는 `resume-kit`(사실 보존), `RenderCV`(YAML PDF), `browser-research`(레퍼런스), `pageseer`(렌더), `DiffPDF`·`Pixelmatch`(회귀), `docrefract`(구조 비교), `Playwright`(브라우저 QA), `ui-ux-suite`(접근성 감사)다. 현재 실행은 로컬 제작과 검증을 우선하고, 원본과 개인정보는 외부로 전송하지 않는다.
