# 14개 조직 합동회의 10라운드

작성일: 2026-08-24

참석: 01~14 전 조직. 독립회의 결과를 교차 검토한 합동 패널 회의다. 외부 도구·실제 채용공고·브라우저 테스트·외부 컨설팅은 이 회의에서 실행하지 않았다.

## 1라운드 — SSOT와 조직 수

- 충돌: 조직도는 14개, 운영모델은 13개, 최초 요청은 11개.
- 합의: 현재 운영 대상은 14개로 두되 공식 조직 수는 최종 승인 전 보류.
- 보류: PDF 시각품질팀을 ATS 문서팀과 분리할 독립 권한.

## 2라운드 — 커리어 전략

- 충돌: 해외 B2B·브랜드사 포함 구형 3트랙과 최신 국내 전시·MICE 전략 혼재.
- 합의: 1차 목표는 국내 PCO·전시주최사·전시장 운영사. 메쎄이상·엑스포럼은 제외.
- 보류: 최신 JD 20~30건 검증 전 시장 수요 확정.

## 3라운드 — 포지셔닝

- 충돌: 전시·행사 프로젝트 기획자, 전시·MICE 고객경험 프로젝트 코디네이터, Customer Experience Coordinator 혼재.
- 합의: 공개 기본 직무명은 `전시·MICE 현장 운영·고객경험 프로젝트 코디네이터`.
- 보류: 실제 공고에서 해당 표현이 통용되는지 미조사.

## 4라운드 — 증거와 성과 수치

- 충돌: 원본 수치를 보여줘야 한다는 의견과 확정 성과 오해를 막아야 한다는 의견.
- 합의: `130% 향상`, `2명→1명`은 삭제하지 않고 `원본 이력서 자기보고 수치 · 검증 대기`로 표시.
- 보류: 원자료·운영기록·제3자 확인 전 verified_fact 승격 금지.

## 5라운드 — 포트폴리오 위계

- 충돌: 럭키드로우를 강하게 전면 노출할지, 디지털 개발자 이미지 위험을 줄일지.
- 합의: `Event Operations → Content & Customer Journey → Digital Operations Improvement` 위계 고정. 럭키드로우는 현장 운영 문제의 디지털 전환 사례로 설명.
- 보류: 채용자 5초 테스트 전 효과 확정 금지.

## 6라운드 — 웹 고객경험

- 충돌: 현재 스크롤 구조가 충분하다는 의견과 클릭 없이 대상·역할이 부족하다는 의견.
- 합의: `정체성 → 세 역량축 → 경력 → 포트폴리오 → 업무 방식 → 연락` 흐름 유지.
- 보류: 390px·768px·1440px 실제 브라우저 테스트 전 사용성 완료 표시 금지.

## 7라운드 — 미디어와 접근성

- 충돌: 영상·실제 iframe을 적극 노출할지 외부 로딩·자동재생 실패를 우려할지.
- 합의: 영상·iframe 유지, poster·텍스트 설명·새 창 링크·기능 설명을 함께 제공.
- 보류: 자동재생·iframe 장애·키보드·저속 네트워크 테스트 미실행.

## 8라운드 — 콘텐츠 자산과 상세 페이지

- 합의:
  - 메인 뉴스레터: 대표 이미지 1~2장
  - 상세 뉴스레터: 확보된 전체 콘텐츠
  - 카드뉴스: 고객 여정 콘텐츠
  - 참가브랜드모집: 별도 모집 캠페인
  - 럭키드로우: 실제 데모와 현장 영상
- 보류: 사용자 보유 원본 전체와 상세 페이지의 완전 일치 여부 추가 대조.

## 9라운드 — PDF·ATS·시각품질

- 충돌: 파스텔 시각 PDF와 단순 ATS PDF를 분리할지 한 장으로 통합할지.
- 합의: 한 장 안에서 ATS 텍스트 순서는 단순하게 유지하고 파스텔은 시각 계층 보조로만 사용.
- 보류: 외부 ATS 파서, 채용자 5초·20초 테스트, 실제 인쇄 가독성.

## 10라운드 — 최종 승인과 운영 루프

- 충돌: 로컬 구현·문서화 완료를 공개 가능으로 볼지 외부 검증 전 보류할지.
- 합의 상태: `문서화 완료 → 로컬 구현 완료 → 외부 검증 대기 → 사용자 승인 대기 → 공개·지원`.
- 보류: 실제 JD 20~30건, 외부 HR, 브라우저, ATS, 외부 컨설팅, 지원 제출·메시지 전송.

## 최종 합의안

1. 목표 방향은 국내 전시·MICE 현장 운영 기반 고객경험 프로젝트 코디네이터.
2. 역량 위계는 `Event Operations → Content & Customer Journey → Digital Operations Improvement`.
3. 웹·PDF·포트폴리오 문구는 `resume.yaml`을 SSOT로 사용.
4. 두 성과 수치는 자기보고·검증 대기.
5. 럭키드로우는 현장 운영 문제를 디지털 도구로 전환한 사례.
6. 뉴스레터 메인은 1~2장, 전체 콘텐츠는 상세 페이지.
7. 사용자 승인 전 문서는 제출용 최종본이 아님.

## 추가 이슈 라운드 — WHO I AM 5초 인지 카피

- 이슈: `채용자가 먼저 알아야 할 것`은 자기소개가 아니라 채용자용 안내문처럼 읽혀 정체성과 맞지 않음.
- 평가 기준: 채용자가 첫 5초 안에 지원자의 직무, 전문 영역, 강점을 파악할 수 있는지 검토.
- 합의 문구: `전시·MICE 현장 운영과 고객경험을 연결하는 프로젝트 코디네이터`
- 보조 설명: `현장 운영을 기반으로 참가자·참가사·운영팀의 흐름을 정리하고, 콘텐츠와 디지털 도구로 경험을 개선해왔습니다.`
- 제외: 미검증 성과 수치와 근거 없이 범위를 넓히는 표현.
- 적용 파일: `index.html`의 WHO I AM 섹션.

## 미합의·미검증

- 공식 조직 수 11·13·14 중 최종 확정
- 목표 직무명의 실제 시장 통용성
- 국내 타깃 공고 20~30건 요구사항
- CRM·영어·리드·예산·P&L의 필수성
- 외부 HR 5초·20초 평가
- 모바일·브라우저·접근성·영상·iframe 검증
- 외부 ATS·인쇄 가독성
- 성과 수치 원자료·제3자 검증

## 실행 우선순위

1. 조직 목록을 운영모델과 조직도에서 일치시킨다.
2. 국내 목표 공고를 수집해 요구사항 매트릭스를 만든다.
3. `resume.yaml` 주장별 증거 상태를 구조화한다.
4. 웹·PDF·포트폴리오 직무명과 세 축을 통일한다.
5. 390px·768px·1440px 브라우저 회귀 테스트를 실행한다.
6. PDF 한글·ATS·인쇄 가독성을 검증한다.
7. 사용자 승인 후에만 지원용 문서·제출 단계로 이동한다.

## 회의 상태

합동회의 10라운드와 독립회의 14개×10라운드는 내부 검토로 완료됐다. 외부 검증·지원 제출·메시지 전송은 완료되지 않았다.
